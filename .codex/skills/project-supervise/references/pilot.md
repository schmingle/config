# Explicit isolated pilot

Run only on a human's explicit pilot request. Use an isolated project/tasks/disposable checkout with permitted effects; agree on connected-service writes first. Configuration review authorizes no live tasks, automations, tickets, or updates. Shorten intervals/batches only for the test and record their actual values.

Exercise these scenarios against actual records/artifacts; report observed passes, failures, untested scenarios, and host limitations separately:

1. **Fresh setup and legacy context:** Supply an old execution chat/schedule for the same project. Verify the invoking task's own ID/title, a new worker named exactly `<supervisor task title> worker`, and no worker automation. Read back the assignment's scope/outcome/validation/authority/start/deadline in Linear before `create_thread`. Verify the supervisor heartbeat's kind, current-task target, exact `$project-supervise` prompt, and active state before creation, which starts the first batch. Persist/read back the returned pairing. Start the cycle immediately. Leave unrelated legacy records unchanged; competing active ownership holds conflicting work.
2. **Oversized ordered queue and quiet Linear:** Supply real approved work materially beyond batch capacity, ordered by project goals, critical path/dependencies, and human priorities. Verify the compact batch references standing rules and the canonical queue without cloning them; temporary limits stay temporary. Finish a tiny first task, then continue with the next eligible item. Block a high-priority path and verify safe independent work continues within scope/ownership/phase gates and the unchanged deadline. Normal Linear status/PR/CI updates need no narrative or routine decision log; comments carry only consequential exceptions. The batch ends at its cleanup/report reserve rather than an artificially small deliverable; no busywork is invented near project completion.
3. **Early idle and unblock:** Exhaust the authorized queue while project work remains, supply a too-narrow assignment, and simulate an observed host continuation failure. Verify a local final report states the exact blocker, evidence, attempted resolution, blocked next action, and smallest unblock. The supervisor corrects scope/queue within authority and dispatches meaningful work after settlement, or escalates a concrete needed decision. Diagnose a missing report/unexplained early end before dependent dispatch rather than assuming success. Newly unresolved blockers cannot silently idle; unchanged surfaced human blockers stay quiet with the heartbeat active. No busywork or repeated unchanged checks fill the time.
4. **Authority limit:** Put the next dependency behind a missing approval, ownership conflict, or unaccepted phase exit. Verify neither aggressive execution nor queue exhaustion creates merge/deploy/production/explicit-skill authority; continue independent eligible work or surface the precise blocker.
5. **Chat loss and current evidence:** Leave a detailed own-chat report, preserve only consequential decisions/approval provenance/proof/recovery state in Linear, then lose the chat. Recover standing scope, ordered queue, batch controls, and next action without a mirrored report. Apply a material evidence delta to one current summary while retaining consequential history/source proof; do not assume revision history preserves removed decisions. Reconcile a new chat-only instruction/result with readback before dependent continuation; current human instructions override stale records. Agent claims/statuses cannot prove approval or acceptance.
6. **Steering and phase gates:** Introduce active and idle-worker discrepancies. Record/read back corrections in Linear before an authorized native steering action; active nudges keep the deadline, while settled idle workers get a complete fresh checkpoint. Verify actual correction evidence and acceptance before dependent work. No cross-task messaging permission is inferred, and denied actions are not rerouted.
7. **Exact-ID resume and partial bootstrap:** Resume after a gap/title changes using the same recorded pair/heartbeat IDs, creating nothing. Simulate lost worker/heartbeat creation responses; recover newly created records through exact assignment checkpoint links and native creation/binding evidence without duplicates, retaining partial bootstrap and completing only never-attempted steps. Wrong heartbeat kind/target/prompt and missing/contradictory bindings require diagnosis, not legacy adoption.
8. **Lost-task recovery and unknown settlement:** Definitively lose a task, recover from Linear, and verify old conflicting work/scheduling settled/retired before creating a safely authorized successor with preserved ID history and stop state. Contrast unreachable tasks, elapsed deadlines, and unknown agents/commands/schedules: these remain blockers unless a separately authorized handoff resolves the conflicts. Do not require new approval when prior authority and verified settlement already suffice.
9. **Deadline, stop, and full acceptance:** Keep useful work running toward the fixed deadline with cleanup/report reserve, then verify settlement/no overlapping batch. For deadline, early blocker, explicit stop, and completion, require a final report in the worker's own chat covering actual work/links, checks/limits, material findings, blocked/skipped work and attempted unblocks, remaining priority order, stop time/deadline, and owned-work settlement/unknowns. Useful detail is allowed; no report is sent to another task or posted wholesale in Linear, and no direct human project question or supervisor identity is required. Verify the supervisor pulls the report and actual evidence; host interruption may prevent a report. Explicit human stop and genuine project completion permit early exit; a worker claim alone cannot establish project acceptance. Include owned work crossing the deadline and verify unresolved settlement is reported honestly. Stop explicitly while Linear is unavailable: cease dispatch and use authorized pause/stop controls immediately, verify execution settlement separately, record the pending checkpoint locally in the task response, and reconcile/read back Linear when reachable. Stale records cannot override the human stop. Queued cycles cannot restart it; only later human authority resumes it. Verify combined project criteria and independent reviews, settle worker/reviewers/writes, publish the final update, and pause/read back the heartbeat. Reinvoking unchanged completed work creates nothing.

Pause test automations only on explicit stop or verified completion. Static checks alone are not a live pilot.
